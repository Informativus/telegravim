# Сборка пакетов Telegravim

Windows x64 и Linux x86_64 собираются вручную через GitHub Actions:
`Windows release package` и `Linux release package`. Выберите проверенный ref
через **Run workflow**. Для стабильного релиза используйте точный итоговый
коммит `main` после PR `develop` → `main`, как описано в
[правилах веток](branch-flow.md). Сборка рабочей ветки не является релизом.

Workflow имеют только `contents: read`, не используют секреты, не отправляют
уведомления, не создают теги и не публикуют релиз. Готовые архивы с контрольными
суммами сохраняются в Actions artifacts на 14 дней. `BUILD-INFO.json` внутри
пакета фиксирует версию, коммит, платформу и конфигурацию Release.

Linux использует официальный образ сборочных зависимостей Telegram,
закреплённый по digest, и проверяет сборку вместе с нативными Vim-тестами.
Windows использует GitHub-hosted `windows-2025`, x64 MSVC, Qt 6 и штатный
`prepare/win.bat`; зависимости сохраняются в кэше по содержимому скриптов
подготовки. При пустом кэше первая сборка существенно дольше повторных.

Автообновление официальным Telegram и автоматическая отправка crash reports
отключены, как в локальном macOS-пакете. Пакеты включают лицензии словарей.
Нативные тесты не заменяют проверку входа, переписки и интерфейса на реальном
аккаунте. Отмечайте эти проверки отдельно в описании опубликованного релиза.

macOS DMG собирается локально из того же коммита `main` с Release, strip,
подписью с entitlements, проверкой codesign и `hdiutil verify`.
