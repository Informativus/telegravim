# Первый этап: локальные теги и защищённый файловый перенос

Согласованный объём: LF-01a + LF-06. Полные требования остаются в
[задании](specification.md), состояние — в [чеклисте](checklist.md).
Пользователь одобрил начало реализации. Настоящий QR-перенос и Android остаются
последующими обязательными этапами LF-01.

Первая поставка от 2026-10-24 отклонена пользователем: отдельное окно
`Local saved tags` и оставшийся вход в Premium не соответствуют задаче.
Исправление должно сохранить штатные выбор реакций/тегов, метки на сообщениях,
управление названиями, панель фильтрации, поиск и клавиатурную навигацию.
Отличается только локальный источник данных и отсутствие требования Premium.
Первый DMG снят с приёмки. Исправленная поставка с нативным интерфейсом принята
пользователем и доставлена в `develop` через PR #81.

## Результат для пользователя

В «Избранном» можно назначить сообщению несколько локальных тегов с названием
и эмодзи, изменить название, удалить тег, обработать выделенную группу сообщений
и найти сохранённые сообщения по сочетанию тегов и текста. Доступна клавиатурная
и Vim-навигация. Эти действия не используют Premium API и не отправляют реакции.

Данные переживают перезапуск. В настройках доступен перенос локальных данных
через зашифрованный файл с отдельным паролем. Перед применением видны состав,
аккаунты, конфликты и неподдерживаемые модули. Повторный импорт не создаёт дублей;
изменение данных во время предпросмотра требует обновить предпросмотр.

## Решения реализации

| Решение | Рассмотренные варианты | Выбор и причина |
| --- | --- | --- |
| Источник данных | Existing KV prefs; отдельная платформа-зависимая БД; JSON-модули | JSON-модули с отдельным защищённым хранением: требования переноса и восстановления не покрыты prefs/cache |
| Атомарность | Последовательная запись профилей; одно переключение поколения | Общее поколение domain с неизменяемыми сегментами и проверяемой фиксацией manifest: импорт нескольких профилей применяется целиком |
| Изменения | Последняя дата выигрывает; версия устройства + явный конфликт | Version vectors и tombstones, явные решения для конкурентных изменений и удаления; неизвестные данные сохраняются |
| Экспорт | Открытый JSON/ZIP; контейнер с паролем | Потоковый аутентифицированный контейнер на OpenSSL, отдельный пароль пакета, без секретов Telegram |
| Отзывчивость | Работа с диском и шифрованием в UI; worker | Worker, отмена и ограниченные порции; callbacks привязаны к времени жизни интерфейса |
| Поиск старых сообщений | Удаление связей при cache miss; загрузка по стабильному ID | Ограниченная загрузка сообщений аккаунта с сохранением связей при недоступности сети/кэша |
| Приёмка | Только пустая инфраструктура; реальный первый модуль | Теги вместе с хранилищем дают реальный сценарий перезапуска и повторного переноса |

Точные версии формата, параметры криптографии, размеры и правила валидации
фиксируются вместе с реализацией и схемами. Совместимость с Android оценивается
по контракту; её работа не заявляется до проверки на настоящем клиенте.

## Разделение работ

- Хранение: domain-owned store, схемы, идентичности, версии и удаления,
  snapshot, подготовка объединения и атомарный commit.
- Теги: модуль `saved_tags`, изменения тегов и связей, массовое назначение,
  библиотека/поиск, получение старых сообщений, клавиатурная навигация.
- Файловый перенос: зашифрованный потоковый пакет, ресурсы, прогресс/отмена,
  проверка целостности, предпросмотр и интерфейс импорта.
- Интеграция: меню сообщений и «Избранного», настройки, локализация, сборка,
  review, проверка свежего DMG и сбор пользовательских замечаний.

## Границы готовности

Наличие реализации не закрывает этап. Нужны существующие применимые проверки,
сборка, наблюдение фактического поведения и пользовательская приёмка свежего
DMG. Новые тесты без отдельного запроса не создаются. Образы из предыдущих
задач не считаются поставкой этого этапа. Коммит, push и PR выполняются после
пользовательской проверки; готовность Desktop, переноса и Android учитывается
раздельно.

## Как проверить повторную сборку

1. В «Избранном» нажмите `Shift+R`, выберите сообщение по подсказке и назначьте
   тег. Проверьте также обычное открытие выбора реакции мышью.
   Он должен сразу появиться у сообщения без перехода в Premium; проверьте
   также развёрнутый выбор эмодзи и повторный клик для снятия тега.
2. Переименуйте тег через его стандартное контекстное меню. Нажмите тег у
   сообщения: должен открыться обычный поиск Telegram с панелью тегов.
   Проверьте несколько тегов одновременно и сочетание тегов с текстом,
   прокрутку старых результатов, клавиатурную и Vim-навигацию.
3. Назначьте тег выделенной группе сообщений. Перезапустите приложение и
   проверьте названия, назначения и восстановление фильтра. Удаление тега
   из контекстного меню панели удаляет и его назначения.
4. Settings → Advanced → `Transfer local data` позволяет экспортировать
   зашифрованный `.tgv` с отдельным паролем не короче 12 символов и открыть
   пакет для предпросмотра импорта. Перед применением видны аккаунты, модули,
   входящие пометки удаления и конфликты. Сессии и ключи Telegram не переносятся.
5. По умолчанию конфликт сохраняет текущую версию и архивирует альтернативу.
   Архив доступен через `Saved conflict versions`; восстановление выполняется
   явным действием. Проверьте повторный импорт, отмену и сохранность данных.
