# Локальные возможности Telegravim: чеклист выполнения

Дата начала: 2026-10-23. Полный объём: LF-01–LF-24 из
[исходного задания](specification.md). Пользователь принял сборку первого этапа
после исправления падения выбора реакций через `Shift+R`. Остальные задачи
и отдельно не подтверждённые проверки сохраняются в полном объёме.

## Порядок работы

1. Оркестратор готовит границы следующего этапа, результат для пользователя и
   критерии проверки; пользователь согласует этап.
2. Агенты реализуют согласованный этап в отдельных рабочих ветках. Все вопросы
   агентов собирает оркестратор; существенные решения выносит пользователю.
3. Оркестратор проверяет интеграцию и готовит свежий macOS DMG из Release:
   strip, подпись с entitlements, `codesign --verify --deep --strict`,
   `hdiutil verify`. Новые тесты без отдельного запроса не создаются.
4. Пользователь проверяет приложение. Замечания исправляются в этом же этапе.
5. Только после принятия пользователем: коммит, push рабочей ветки, PR в
   `develop`, обязательные проверки и merge через PR. Прямой push запрещён.
6. Чеклист обновляется по фактическим доказательствам, затем согласуется
   следующий этап. Публикация стабильного релиза — отдельное действие.

Статусы Desktop, переноса данных, пользовательской приёмки, доставки через PR
и Android учитываются отдельно. Готовый интерфейс без сохранения и переноса
не закрывает задачу. Ожидание Android не отменяет Desktop-работу, но не позволяет
объявить полный план выполненным.

Рабочие предположения, следующие из исходной постановки:

- Продукт рассчитан на личный архив нескольких аккаунтов, включая большие
  материалы и модели; объёмы и лимиты задаются явно, операции идут порциями.
- Тяжёлая обработка выполняется вне UI, поддерживает отмену; реальные время и
  память измеряются, целевые числа не объявляются без измерений.
- Данные локальных функций защищены; экспорт не включает Telegram-секреты;
  локальные AI/перевод не переключаются на сеть без отдельного решения.
- Повреждения и обрывы сохраняют последнее исправное состояние; конкурирующие
  изменения и удаление не разрешаются молча по часам устройства.
- Общий контракт и миграции поддерживаются вместе с Desktop; адаптация Android
  проверяется отдельно. Ни одна платформа не выбрасывает неизвестные данные.

## Общий контракт: обязателен для каждой функции

- [ ] Версионированный JSON — источник собственных структурированных данных;
  на диске он защищён шифрованием аккаунта или совместимым контейнером.
- [ ] Объявлены `module_id`, `schema_version`, валидация, миграции;
  неизвестные поля и модули сохраняются без потерь и без выполнения.
- [ ] Аккаунты определяются средой и стабильным `user_id`; Telegram ID —
  десятичные строки; сообщения включают аккаунт, тип/ID собеседника и ID сообщения.
- [ ] Собственные объекты имеют UUID, версии для конкурентного редактирования
  и записи об удалениях; часы устройства не решают конфликты единолично.
- [ ] Вложения имеют переносимые ссылки, размер и SHA-256; абсолютные пути
  не являются частью переносимого контракта.
- [ ] «Перенести всё» включает все зарегистрированные модули, пользовательские
  файлы, результаты и доступные переносимые ресурсы, включая совместимые
  лицензированные модели; отсутствие движка не уничтожает результаты.
- [ ] Облачные сообщения представлены ссылками; сохранённые локально тексты и
  разрешённые медиа входят в полный перенос. Охват сохранённой истории виден.
- [ ] Сессии Telegram, auth keys, пароли, токены и секреты устройства не
  экспортируются; секретные настройки требуют повторной настройки.
- [ ] Импорт показывает состав, размер, аккаунты, конфликты и несовместимости;
  по умолчанию объединяет без молчаливого удаления существующих данных.
- [ ] Повторный импорт не создаёт дублей; обрыв не применяет пакет частично;
  неподдерживаемые модули переживают последующий экспорт.
- [ ] Автоматизация после импорта выключена до явного выбора исполнителя;
  незавершённые операции не запускаются заново как новые.
- [ ] QR связывает устройства для защищённой передачи; медиа и модели
  передаются вне QR. Реальный Android-перенос проверяется отдельно.
