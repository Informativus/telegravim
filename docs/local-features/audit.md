# Основа для локальных возможностей: аудит перед реализацией

Дата: 2026-10-23. Это инвентаризация исходников, не результат проверки поведения.
Полные требования сохранены в [задании](specification.md), состояние выполнения —
в [чеклисте](checklist.md). Аудит выполнен тремя агентами: хранение/перенос,
существующие функции, сборка/доставка. Новые тесты и изменения приложения не
создавались; сборка не запускалась.

## Основные выводы

- LF-01 требует новой общей инфраструктуры. Шифрование локальных файлов,
  JSON, QR, архивы и криптографические библиотеки уже есть, но сами по себе не
  обеспечивают перенос модулей и транзакционный импорт.
- KV preferences нельзя считать готовым долговременным JSON-хранилищем:
  `storage_account.cpp` сбрасывает dirty flag до записи, результат commit
  не проходит к вызывающему, а чтение повреждённых prefs очищает их ссылку.
  Для новых пользовательских данных требуется явная ошибка и сохранение
  последнего исправного состояния.
- Account storage изолирует файлы аккаунтов, но ключ шифрования создаётся на
  уровне локального domain. Этот ключ и Telegram-сессии не входят в экспорт.
- `FullMsgId` не содержит аккаунт. Переносимые ссылки должны отдельно хранить
  среду, user ID аккаунта, тип и bare ID собеседника, ID сообщения строками.
- Существующий folder archive не шифруется и может пропускать исчезнувшие
  файлы; cloud-blob распаковка держит архив в памяти. Для большого согласованного
  переноса их нельзя использовать без изменения соответствующих гарантий.
- QR-вход Telegram относится к авторизации. Он не реализует перенос локальных
  данных, привязку устройства к ключу и возобновление передачи.
- Локальная расшифровка находится в отдельном
  [PR #73](https://github.com/Informativus/telegravim/pull/73).
  На момент аудита она ещё не входила в `develop`. Её доставка — зависимость LF-13.
- Существующие локальные доработки и новая задача должны иметь раздельные diff.
  Состав пользовательской сборки необходимо проверить, чтобы сохранить уже
  используемые возможности. Сборочное дерево привязано к конкретным исходникам.

## Ограничения доказательств

- Поиск по production sources/docs не выявил общий transfer manifest и модули
  из задания. Это результат ограниченного аудита исходников, не формальная
  гарантия отсутствия любого связанного кода.
- Существующий перевод может выбирать MTProto при недоступности платформенного
  провайдера. Поддержка провайдера сама по себе не доказывает локальную обработку.
- Текущие лимиты аккаунтов — 3/6; чтение storage также ограничивает число/индексы.
  Изменение одного UI-лимита не выполняет LF-12.
- Истории требуют наблюдения со стороны владельца; разделение API-путей в коде
  не доказывает скрытый просмотр. Условный характер LF-10 сохраняется.
- Успешные исходники/сборка/PR не заменяют пользовательскую проверку DMG,
  сохранение данных и настоящий Desktop → Android перенос.
