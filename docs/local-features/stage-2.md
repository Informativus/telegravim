# Второй этап: локальные закрепления

Согласован 2026-10-24 после доставки LF-01a + LF-06. Объём — Desktop-часть LF-18
из [исходного задания](specification.md). Пользователь подтвердил продолжение
предложенного этапа. Рабочая ветка: `feature/local-pinned-items`.

## Пользовательский результат

В главном списке, архиве, существующих облачных папках и разделах собственного
«Избранного» можно закреплять элементы сверх облачной квоты. Используются
штатные команды Telegram, значки, перетаскивание и клавиатурная навигация.
Новые действия закрепления, открепления и изменения порядка сохраняются локально
и переносятся общим зашифрованным файловым механизмом.

Существующие облачные закрепления образуют исходное состояние. Локальное
открепление скрывает такое закрепление на этом устройстве и сохраняется как
явное переопределение. Серверное обновление списка не стирает локальные данные.
Одинаковый чат в разных областях имеет независимое закрепление.

## Решения и границы

- Принят единый локальный способ записи новых действий. Альтернатива «облако
  до квоты, локально после» отклонена: одинаковая команда неожиданно меняла бы
  другие устройства в зависимости от текущего числа закреплений.
- Облачное состояние и отображаемый объединённый порядок разделены. Простое
  снятие ограничения не подходит: `PinnedList::applyList` очищает порядок,
  а серверные обновления непосредственно переписывают закрепления.
- Порядок хранится отдельной версионированной записью; конфликтующие перестановки
  попадают в существующий предпросмотр импорта. Часы устройства не определяют
  победителя. Повторный импорт не создаёт вторую копию одного закрепления.
- Неизвестные поля и недоступные объекты сохраняются. Отсутствие чата в памяти
  или текущем отображении не означает его удаления из локальных данных.
- Смена аккаунта, перенос чата в архив и удаление облачной папки не должны
  переносить закрепления в другую область. После обнаруженного удаления
  повторное использование серверного ID папки получает новую локальную идентичность.
- Область локальной папки с UUID резервируется в контракте; реальный интерфейс
  локальных папок подключается в LF-03. Форумные темы и закреплённые сообщения
  внутри чатов не относятся к перечисленным в LF-18 объектам.
- Android остаётся обязательной отдельной приёмкой LF-18. Desktop-сборка,
  файловый перенос между Desktop и отображение QR не закрывают Android.
- Очистка истории сохраняет закрепление. Удаление диалога записывает локальное
  открепление во всех известных областях чатов одной операцией, чтобы новое
  сообщение не восстанавливало старый pin. Разделы «Избранного» независимы.

## Хранение и надёжность

Модуль `pinned_items` использует существующий зашифрованный Store, стабильный
аккаунт и переносимые ссылки на объекты. Собственные записи имеют UUID,
вектор версий и пометки удаления. Данные не содержат Telegram-сессий и ключей.
Общий формат, правила объединения и неизвестные поля сохраняются для Android.

Запись идёт последовательно вне UI; ошибка не оставляет интерфейс с якобы
сохранённым состоянием. Перезапуск должен дождаться незавершённых локальных
записей. Импорт применяется атомарно. Исходные облачные списки остаются пригодны
для штатных запросов; локальные операции не вызывают pin/reorder/filter-mutation API.
Обычная загрузка информации о чатах разрешена.

Рабочая нагрузка — личные списки нескольких аккаунтов, включая превышение
облачных квот. В каждой области допускается до 4096 локальных закреплений и
ссылок порядка; действуют также общие ограничения размера JSON и записей.
Превышение отклоняется с ошибкой, без скрытого удаления элементов. Загрузка
недоступных объектов ограничена по числу одновременных запросов и повторов.
Измерения производительности на предельном размере ещё не выполнены.

Формат и правила объединения описаны в
[контракте `pinned_items`](pinned-items-format.md).

## Приёмка Desktop

- [ ] Штатное закрепление сверх облачной квоты на аккаунте без Premium во всех областях.
- [ ] Открепление и перестановка смешанного списка согласованы с его значками и навигацией.
- [ ] Перезапуск, полная и частичная серверные загрузки сохраняют локальный порядок без дублей.
- [ ] Архив, несколько папок и аккаунтов изолированы; исчезновение папки не переназначает записи.
- [ ] Очистка истории сохраняет pin; удаление диалога не возвращает его после нового сообщения.
- [ ] Экспорт → импорт → повторный импорт сохраняет порядок, удаления и неизвестные поля.
- [ ] Конкурирующие перестановки показываются в предпросмотре; недоступные записи сохраняются.
- [ ] Локальные команды не отправляют серверные мутации закреплений и папок.
- [x] Существующие применимые проверки и сборка выполнены; новые тесты без запроса не написаны.
- [x] Свежий Release DMG обработан strip, подписан с entitlements и проверен codesign/hdiutil.
- [x] Пользователь проверил и принял DMG; можно выполнять коммит, push, PR и merge.
- [ ] Android-перенос и восстановление проверены отдельно либо остаются явно открытыми.

## Состояние

2026-10-24: реализация Desktop подготовлена для пользовательской проверки.
Полная сборка macOS Release для arm64 завершилась успешно. Проверены diff,
UTF-8 без BOM, LF и синтаксис JSON Schema; новые тесты не добавлялись.
Дополнительный просмотр кода закрыл найденные проблемы удаления диалогов,
жизненного цикла скрытых разделов «Избранного», восстановления после ошибок
загрузки и открепления после импорта большого списка.

`codesign --verify --deep --strict` и `hdiutil verify`.
