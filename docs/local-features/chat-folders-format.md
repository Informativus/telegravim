# `chat_folders`, версия 1

Модуль использует общий зашифрованный Store и контракт файлового переноса.
Аккаунт определяется парой `environment` / `user_id`. Временные отрицательные
идентификаторы локальных папок и Telegram access hash не входят в переносимые
данные. Оформление облачной папки ссылается на её серверный ID и локальную
инкарнацию из `pinned_items`.

## Записи

Все записи содержат `id`, `version_vector`, `deleted` и `kind`. UUID записи
вычисляется детерминированно из аккаунта и её смыслового ключа. Повторный импорт
обновляет ту же запись. Удаление хранится как tombstone с новым вектором версий.

| `kind` | Поля | Значение |
| --- | --- | --- |
| `folder` | `folder_id`, `title`, `position`, `rules` | Переносимый UUID, название, порядок и правила папки |
| `folder` | `icon`, `color`, `title_entities`, `static_title` | Необязательное оформление и сущности названия |
| `member` | `folder_id`, `peer`, `mode` | Явное включение (`include`) или исключение (`exclude`) чата |
| `settings` | `scope`, `tags_enabled` | Настройки аккаунта; `scope` всегда равен `account` |
| `cloud_color` | `scope`, `color_index` | Локальный цвет облачной папки; `null` отключает метку |

`peer` содержит `peer_type` (`user`, `chat`, `channel`) и десятичный `peer_id`
как строку. Исключение имеет приоритет, если при объединении появились обе
активные записи для одного чата. Недоступный чат остаётся в данных и может
появиться в интерфейсе после загрузки обычных сведений Telegram.

`title_entities` хранит объекты с `type`, `offset`, `length` и необязательным
`data`. Смещения и длины относятся к UTF-16, как в Telegram Desktop.
Неизвестные типы сохраняются без исполнения. `static_title` управляет анимацией
сущностей названия.

Запись `settings` имеет детерминированный UUID, вычисленный из аккаунта и
ключа `settings:account`. Она появляется после локального изменения
переключателя тегов; отсутствие записи означает, что локальное значение не
задано. Неизвестные поля этой записи сохраняются при обновлении
`tags_enabled`.

`cloud_color.scope` использует `filter:<id>:<incarnation_uuid>` из
`pinned_items`. После обнаруженного удаления облачной папки её старый цвет
не применяется к новой папке с повторно использованным серверным ID. Для
переноса оформления нужен также модуль `pinned_items` с этой инкарнацией.
Отсутствие записи оставляет серверный цвет; явный `null` выбирает «Без метки».
Поддерживаются цвета 0–6; будущие значения 7–255 сохраняются без применения.
UUID записи вычисляется из аккаунта и ключа `cloud_color:<scope>`.
Цвет не записывается в `messages.updateDialogFilter`; изменение только цвета
не отправляет запрос изменения облачной папки.

## Правила

`rules` — массив декларативных объектов с `op` и `enabled`. Поддерживаемые
операторы соответствуют штатным настройкам папки:

| Оператор | Условие |
| --- | --- |
| `contacts` | Пользователь из контактов |
| `non_contacts` | Пользователь вне контактов |
| `groups` | Группа |
| `channels` | Канал |
| `bots` | Бот |
| `no_muted` | Штатное исключение чатов с отключёнными уведомлениями |
| `no_read` | Штатное исключение прочитанных чатов |
| `no_archived` | Исключение архива |

Типы чата объединяются через «или», выбранные исключения применяются к этому
результату. Явное включение действует независимо от правил; явное исключение
имеет приоритет. Неподдерживаемый `op` сохраняется и не выполняется. Дополнительные
поля известных правил и записей сохраняются при обычном редактировании.

## Закрепления и перенос

Закрепления и их порядок принадлежат модулю `pinned_items`, область
`local:<folder_uuid>`. Они не преобразуются в облачные ID папок. Удалённая папка
не показывается; её UUID не назначается новой папке.

Конкурирующие изменения используют общий предпросмотр импорта. «Сохранить обе»
оставляет текущую запись активной и сохраняет альтернативу в архиве конфликтов,
без клонирования UUID и нарушения ссылок состава.

Ограничения безопасности: до 4096 активных папок и до 4096 явных включений
и исключений каждого вида в одной папке. Дополнительно действуют общие пределы
размера модуля, записи, JSON и пакета. Это не Telegram Premium-квоты и не
заявление о проверенной производительности на предельном объёме.

Полная структура находится в [JSON Schema](local-data.schema.json).
Android должен читать общий формат, но межплатформенная реализация и проверка
остаются отдельной частью плана.
