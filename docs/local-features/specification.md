# Telegravim: задачи для локальных возможностей без Premium

Дата: 23 октября 2026 года.

Статус: план разработки. Создание этого документа не означает, что перечисленные функции уже реализованы или проверены в установленном приложении.

Цель: реализовать полезные локальные аналоги Premium-функций в Telegravim и заранее подготовить перенос всех созданных ими данных в будущий Android-клиент через сканирование QR-кода.

В плане перечислены реализуемые возможности и частичные аналоги. Скрытый просмотр историй включён как условная исследовательская задача: выпуск зависит от подтверждения результата на стороне владельца истории.

## Обязательный контракт JSON и переноса для каждой задачи

Эти требования входят в каждую задачу LF-01–LF-24. Наличие интерфейса без сохранения и переносимости не считается завершением задачи.

- Хранить собственные структурированные данные функций в версионированном JSON: настройки, пользовательские записи, связи с сообщениями, порядок элементов, правила, результаты обработки и состояние удаления.
- На диске JSON защищать существующим механизмом шифрования аккаунта или совместимым защищённым контейнером. JSON не должен означать открытый текст переписки в общедоступном файле.
- Использовать общий формат для Desktop и Android. Дополнительный поисковый индекс допустим, но должен восстанавливаться из JSON и переносимых материалов.
- Для каждой функции определить `module_id`, `schema_version`, правила валидации, миграции и поведения при неизвестных полях.
- Telegram-идентификаторы хранить десятичными строками. Аккаунт определять через среду Telegram и стабильный `user_id`; собеседника — через тип и ID; сообщение — через аккаунт, собеседника и ID сообщения. Не использовать позицию аккаунта, указатель или путь на диске как переносимый идентификатор.
- Собственным объектам присваивать UUID. Для изменяемых объектов хранить метаданные версий, позволяющие обнаружить конкурентное редактирование, и записи об удалениях. Одного времени на часах устройства для разрешения конфликтов недостаточно.
- Вложения хранить отдельными файлами с переносимыми ссылками из JSON, размером и SHA-256. Абсолютные пути Desktop не должны требоваться Android-клиенту.
- Переносить все данные созданных локальных функций: теги, папки, закрепления, шаблоны, задачи, результаты AI, переводы, расшифровки, оформление, правила, пользовательские файлы и доступные переносимые ресурсы.
- Уже загруженные модели включать в перенос, когда их формат и лицензия это допускают. Если целевое устройство не может их использовать, сохранять сведения о модели и явно показывать необходимость совместимой модели. Не терять пользовательские результаты из-за отсутствия движка.
- Облачные сообщения идентифицировать ссылками на Telegram; сохранённые локально тексты и разрешённые медиа передавать при полном переносе. Пакет не обещает автоматически содержать всю никогда не загружавшуюся историю Telegram.
- Не переносить Telegram-сессии, `auth_key`, пароли, секреты системного хранилища, временные токены и ключи другого устройства. На телефоне пользователь входит в нужный Telegram-аккаунт обычным способом. Секретные настройки передаются как ссылки на требующие повторной настройки учётные данные, без раскрытия значений.
- Перед импортом показать состав, объём, сопоставление аккаунтов, конфликты и несовместимые модули. По умолчанию объединять данные без молчаливого удаления существующих записей.
- Повторный импорт одного пакета не создаёт дубликатов. Обрыв передачи не оставляет частично применённый набор данных.
- Неизвестный Android-клиенту модуль сохранять без изменений и поддерживать его последующий экспорт. Его выполнение откладывается до появления поддержки.
- После импорта настройки автоматизации сохраняются, но новая копия устройства не начинает самостоятельно отправлять сообщения. Включение исполнителя выполняется отдельно, с явным выбором устройства.
- Сканирование QR связывает устройства и запускает защищённую передачу пакета. Большой JSON, медиа и модели не помещаются непосредственно в один QR-код.

### Формат пакета

```text
telegravim-transfer/
  manifest.json
  profiles/
    <profile-uuid>/
      account.json
      modules/
        saved_tags.json
        chat_folders.json
        pinned_items.json
        quick_replies.json
        ...
  assets/
    <sha256>
```

Это логическая структура внутри защищённого пакета. Большие модули разрешено разделять на несколько JSON-файлов с индексом в манифесте; один огромный документ не должен переписываться после каждого действия.

Пример переносимой записи тега; окончательная JSON Schema должна быть разработана в LF-01:

```json

  "module_id": "saved_tags",
  "schema_version": 1,
  "account": {
    "environment": "production",
    "user_id": "123456789"
  },
  "tags": [
    {
      "id": "c7311433-561f-4b94-9bb1-d91a44e906bc",
      "title": "Идеи",
      "emoji": "💡",
      "created_at": "2026-10-23T12:00:00Z",
      "updated_at": "2026-10-23T12:00:00Z",
      "version_vector": {
        "fa34ee50-a898-4357-9472-c76665793440": 1
      },
      "deleted": false
    }
  ],
  "bindings": [
    {
      "id": "16b8070b-ec43-4b20-9be3-c47affcc8df1",
      "tag_id": "c7311433-561f-4b94-9bb1-d91a44e906bc",
      "message": {
        "peer_type": "user",
        "peer_id": "123456789",
        "message_id": "4567"

```

В примере указана копия сообщения в «Избранном», а не ID исходного сообщения в другом чате. Версии необходимы и для тегов, и для связей: удаление связи должно переноситься так же корректно, как создание.

## LF-01. Общее JSON-хранилище и перенос Desktop → Android через QR

**Сложность:** 5/5. **Тип:** инфраструктура для всех остальных задач.

**Сделать:**

- Определить JSON Schema, версионирование модулей, миграции, привязку к аккаунтам, записи об удалениях и правила объединения.
- Реализовать атомарное сохранение JSON, согласованный снимок для экспорта и транзакционное применение импорта. Повреждённые записи не должны молча уничтожать исправные данные.
- Добавить реестр модулей: каждая функция обязана объявить свои данные и вложения, чтобы «Перенести всё» действительно включало все поддерживаемые модули.
- Создавать QR с версией протокола, одноразовым идентификатором передачи, данными подключения и привязкой к ключу отправителя. После сканирования — подтверждение пары устройств и передача через защищённый канал по локальной сети или точке доступа.
- Использовать стандартный защищённый транспорт и проверенные криптографические библиотеки. QR должен истекать, повторное использование завершённой сессии отклоняется, соединение с другим ключом не принимается.
- Передавать пакет потоково, проверять целостность, поддерживать отмену и возобновление. Ограничивать объём, вложенность JSON и распаковку, проверять пути вложений.
- Предусмотреть тот же импорт из зашифрованного файла, когда устройства не могут связаться напрямую.
- Разделить поставку на Desktop-контракт/экспорт и последующий Android-импорт. На Android использовать системное хранилище ключей и адаптацию переносимых ресурсов к платформе.

**JSON и Android:** `manifest.json`, `account.json`, JSON каждого модуля и реестр вложений. Внутренние базы, индексы и пути платформ не являются форматом обмена.

**Готово, когда:** все зарегистрированные модули проходят экспорт → импорт → повторный экспорт без потери смысла; повторный импорт не дублирует данные; удаления и конфликты обрабатываются явно. Полная задача закрывается только после реального переноса Desktop → Android через QR. До появления Android-клиента отмечать завершённой только Desktop-часть.

## LF-02. Локальные AI-инструменты и резюме

**Сложность:** 5/5. **Тип:** локальный аналог. **Зависит от:** LF-01.

**Сделать:**

- Добавить исправление текста, переформулировку, сокращение, изменение стиля и резюме выбранных сообщений или расшифровок.
- Использовать локальный движок; выбирать модель после измерения качества русского языка, скорости и памяти на целевых устройствах. Поддержать отмену, очередь и отключение тяжёлой обработки.
- Дать пользователю библиотеку собственных стилей и инструкций. Результат сначала показывать для просмотра, изменения исходного сообщения выполнять только по действию пользователя.
- Не переключаться на внешний AI-сервис при ошибке локального движка. Контекст ограничивать выбранным пользователем объёмом.

**JSON и Android:** модуль `ai_tools`: настройки, пользовательские стили, инструкции, сохранённые результаты, ссылки и отпечатки исходных сообщений, модель и её версия. На Android восстановить результаты даже без модели; параметры ускорения и объём памяти подобрать заново.

**Готово, когда:** обработка работает без сетевого сервиса после подготовки модели; интерфейс остаётся отзывчивым; перенос сохраняет результаты и стили. Качество и ресурсные ограничения измерены, а не объявлены по факту запуска.

## LF-03. Локальные папки и расширенные фильтры чатов

**Сложность:** 5/5. **Тип:** локальный аналог. **Зависит от:** LF-01.

**Сделать:**

- Добавить папки сверх облачной квоты, собственный состав, исключения и правила по доступным свойствам чата.
- Разделить локальные и облачные идентификаторы; совместить оба вида папок в интерфейсе, навигации и счётчиках.
- Поддержать локальное количество чатов без Premium-квоты, обновление состава по событиям и восстановление после перезапуска.

**JSON и Android:** модуль `chat_folders`: UUID папок, названия, состав, правила, исключения, цвета и порядок. Android должен интерпретировать общий декларативный формат правил; неизвестные операторы сохранять без выполнения.

**Готово, когда:** изменения Telegram не стирают локальные папки; один чат может состоять в нескольких папках; перенос восстанавливает состав и правила для того же аккаунта.

## LF-04. Локальный поиск по выбранной переписке и сохранённым результатам

**Сложность:** 5/5. **Тип:** частичный аналог расширенного поиска. **Зависит от:** LF-01.

**Сделать:**

- Индексировать выбранные пользователем доступные чаты, локальные заметки, расшифровки и результаты обработки.
- Загружать и обрабатывать историю постепенно, соблюдать серверные ограничения; явно показывать охват индекса.
- Поддержать фильтры по чатам, датам, типам содержимого и локальным тегам. Обновлять индекс при изменении или подтверждённом удалении сообщения.
- Выполнять поиск офлайн по имеющимся данным. Не представлять его как поиск по всем публичным каналам Telegram.

**JSON и Android:** модуль `local_search`: выбранные источники, сохранённые запросы, переносимые документы, их версии и состояние охвата. Индекс платформы перестраивается; локально сохранённый исходный материал передаётся в пакете.

**Готово, когда:** найденное сообщение корректно открывается; неполный индекс обозначен; после переноса результаты восстанавливаются из переносимых данных без необходимости повторно скачивать уже переданные материалы.

## LF-05. Локальный расширенный редактор и совместимая отправка

**Сложность:** 5/5. **Тип:** частичный аналог Rich Formatting. **Зависит от:** LF-01.

**Сделать:**

- Использовать существующий редактор для локальных документов и черновиков с заголовками, списками, таблицами и вложениями.
- Поддержать сохранение, повторное открытие и экспорт в открытые форматы.
- Для отправки без Premium предоставлять предварительный просмотр преобразования в поддерживаемый текст и вложения либо обычный файл. Показывать потерю форматирования до отправки.

**JSON и Android:** модуль `rich_documents`: стабильная модель блоков, UUID документа, связи с чатами, структура вложений, ревизии и черновики. Не сохранять документ только как состояние Desktop-виджетов; неизвестные блоки Android сохраняет для последующего редактирования.

**Готово, когда:** документ переживает перезапуск и перенос; обычный клиент получателя открывает отправленный результат; неподдерживаемые блоки не пропадают молча.

## LF-06. Теги и поиск в «Избранном»

**Сложность:** 4/5. **Тип:** локальный аналог. **Зависит от:** LF-01.

**Сделать:**

- Добавить несколько тегов на сообщение: эмодзи, название, переименование, удаление и массовое назначение.
- Использовать существующее меню рядом с реакциями, добавить панель тегов и фильтрацию по сочетанию тегов и текста.
- Разделить локальные теги и серверные реакции; локальные операции не отправлять в Premium API.
- Сохранять связи со старыми сообщениями, подгружать сообщения по необходимости; отсутствие в кэше не трактовать как удаление. Обеспечить Vim-навигацию.

**JSON и Android:** модуль `saved_tags`: определения тегов, связи с копиями сообщений в «Избранном», порядок, настройки фильтра, версии и удаления. JSON является источником метаданных; счётчики вычисляются из связей.

**Готово, когда:** аккаунт без Premium назначает и переименовывает теги, находит старые сообщения после перезапуска; перенос восстанавливает все связи без затрагивания чужого аккаунта.

Основа: [документация тегов](https://core.telegram.org/api/saved-messages). Нативное переименование требует Premium, поэтому нужен локальный путь: [messages.updateSavedReactionTag](https://core.telegram.org/method/messages.updateSavedReactionTag).

## LF-07. Локальные приветствия и автоответы

**Сложность:** 4/5. **Тип:** частичный аналог Business. **Зависит от:** LF-01, LF-16.

**Сделать:**

- Добавить правила приветствия, рабочего времени и ответа об отсутствии с предпросмотром адресатов и текста.
- Исполнять правила только при явно включённой автоматизации. Исключить циклы автоответов, повторную обработку старых сообщений и массовую отправку при восстановлении сети.
- Вести журнал выполнения. При неопределённом результате отправки сначала выяснять состояние, не повторять сообщение автоматически.

**JSON и Android:** модуль `auto_replies`: правила, шаблоны, расписания, исключения, UUID операций и обработанных событий. После переноса настройки сохранены, но исполнитель на новом устройстве выключен до явного выбора; состояние незавершённой операции не превращается в новую отправку.

**Готово, когда:** перезапуск и потеря сети не дают дубликатов; понятна зависимость от работающего клиента. Для Android отдельно проверены ограничения фоновой работы.

## LF-08. Повторяющиеся сообщения и напоминания

**Сложность:** 4/5. **Тип:** частичный аналог. **Зависит от:** LF-01.

**Сделать:**

- Добавить повторяющиеся личные напоминания и явно настроенные отправки обычных сообщений.
- Учитывать часовой пояс, переходы времени, сон устройства, пропущенные события и отмену серии.

## LF-10. Проверка и реализация локального скрытого просмотра историй

**Сложность:** 4/5 из-за неопределённости поведения сервера. **Тип:** условный частичный аналог. **Зависит от:** LF-01 и подтверждения исследовательского этапа.

**Установлено по коду:** получение содержимого и регистрация просмотра идут разными путями. `Stories::markAsRead()` планирует вызовы `stories.readStories`, а для некоторых историй — `stories.incrementStoryViews`. Это основание для проверки локального режима, но не доказательство невидимости.

**Сделать:**

- Сначала проверить гипотезу на двух контролируемых аккаунтах: один публикует историю, второй без Premium смотрит её в исследуемом режиме. Нужны наблюдение владельца и обычный просмотр для сравнения.
- Если гипотеза подтверждается, отделить локальное состояние просмотренного от серверных отметок; проверить все пути открытия, перехода, предзагрузки, закрытия и отложенной отправки.
- Особо проверить последующий обычный просмотр другой истории того же автора: `readStories` использует максимальный ID, поэтому поздний вызов может затронуть ранее открытые истории. Если эффект ограничен, точно описать это в интерфейсе и критериях доступности.
- Проверить выход из приложения, повторный запуск, восстановление сети и переключение режима. Не пытаться удалять уже зарегистрированный сервером просмотр.
- До подтверждения результата не включать возможность в обычный интерфейс и не показывать обещание скрытого просмотра. Если предпосылка не подтверждается, закрыть исследование с доказательствами без фиктивного переключателя.

**JSON и Android:** модуль `story_view_preferences`: настройки, локальные отметки и версия проверенной реализации. Активный режим и предполагаемые гарантии Desktop не переносить как доказанный статус Android: Android должен отдельно пройти тот же сценарий. Списки зрителей и серверные права не являются локальным состоянием функции.

**Готово, когда:** владельцу истории не появляется просмотр во всех заявленных поддерживаемых сценариях, включая отложенные события; границы результата явно установлены. Проверки должны различать регистрацию просмотров активных и сохранённых в профиле историй.

Документация: [readStories](https://core.telegram.org/method/stories.readStories), [incrementStoryViews](https://core.telegram.org/method/stories.incrementStoryViews). Официальный [Stealth Mode](https://core.telegram.org/method/stories.activateStealthMode) остаётся отдельной серверной возможностью. Условия распространения требуют отдельного учёта: пункт 1.4 [Telegram API Terms](https://core.telegram.org/api/terms) запрещает вмешательство в статусы прочтения; техническая проверка не подтверждает соответствие этим условиям.

## Общие критерии завершения задач

- Функция выполняет заявленный сценарий на аккаунте без Premium; частичный аналог ясно обозначает свою область действия.
- Данные переживают перезапуск, сохраняются в JSON и входят в «Перенести всё» вместе со своими файлами.
- Экспорт и импорт не смешивают аккаунты, не теряют неизвестные поля и не создают дубликаты. Поддерживаются изменения и удаления.
- Установлены границы офлайн-работы: локальные настройки доступны без сети, отсутствующие облачные сообщения требуют обычной загрузки.
- Проверены отклик интерфейса, память и фоновые операции на большом личном архиве. Данные обрабатываются порциями; тяжёлые операции отменяемы.
- Проверка использует существующие проверки проекта, сборку и наблюдение реального поведения. Создание новых тестов не входит в этот план без отдельного запроса.
- Изменения реализации проходят отдельную рабочую ветку и PR. Для передачи пользователю macOS-сборки нужен свежий DMG с проверенными подписью и образом.
- В отчёте отдельно указано: что подтверждено в Desktop, что подтверждено в JSON-переносе и что ещё ожидает Android-реализации.
