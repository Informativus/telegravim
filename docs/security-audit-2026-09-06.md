# Аудит безопасности Telegravim — 6 сентября 2026

## Результат и границы

Проверены изменения форка, границы блокировки приложения, обработка клавиатуры,
буфер обмена, локальное управление, сохранение медиа, зависимости и CI.
Подтверждённые дефекты и выявленные опасные конструкции исправлены локально.
Основная функциональность Vim, форматы медиа и штатные ограничения Telegram
сохранены. Полное отсутствие уязвимостей этим аудитом не доказано.

Исходная база сравнения — `f0ee75edef45fc1d6f3828e56a5d7600643136a2`
(Telegram 7.1.3), исходная ветка аудита — `vim-keymap`. В начале аудита HEAD был `8a71e448bd`;
параллельное изменение документации довело его до `758d9d06bd`.
Эта сторонняя работа сохранена. На последнем HEAD отличие от базы составляет
117 файлов, 18 528 добавленных и 301 удалённую строку; отдельно просмотрены
изменения `Telegram/lib_ui` и `Telegram/lib_base`.
Исправления подготовлены для релиза `2026.09.06-100` по схеме
`fix/security-audit-20260906` → PR в `develop` → PR в `main`.

Модель угроз: содержимое сообщений и файлов приходит из недоверенного источника;
заблокированное приложение не должно выдавать данные через Vim или automation;
процессы другого локального пользователя не должны управлять клиентом.
Процесс с тем же UID и доступом к профилю ОС, root и скомпрометированная ОС
не изолируются локальным сокетом или кодом приложения.

## Исправления

Приоритеты ниже — оценка риска для клиента, а не присвоенные CVSS-баллы.
Для конструкций с нарушением времени жизни указана возможность сбоя;
эксплуатация для исполнения кода не доказана.

| Приоритет | Проблема и условие | Исправление и сохранённое поведение |
| --- | --- | --- |
| Высокий: приватность | Глобальный журнал клавиш мог сохранять фрагменты ввода в текстовых полях, включая пароль и код входа. | Ввод из стандартных редакторов, `Ui::InputField`, дочерних receiver и виджетов с sensitive/hidden hints исключён. Решение о подавлении фиксируется до dispatch и сохраняется при вложенных событиях и смене фокуса. Навигационные команды по-прежнему диагностируются. |
| Высокий: граница блокировки | Проверки блокировки не предшествовали всем глобальным Vim handlers; automation не имела общего запрета при passcode lock. | Ранняя проверка блокировки приложения/активного окна; automation отклоняется до чтения или изменения настроек. История клавиш очищается при блокировке и logout. |
| Высокий: приватность | Отложенное копирование фотографии могло завершиться после блокировки или изменения исходного сообщения. | Блокировка отменяет подписку; перед копированием повторно проверяются сообщение, соответствие фотографии и запреты копирования. Отмена сохраняется и после последующей разблокировки. |
| Средний: время жизни | Callback мог менять registry handlers во время обхода либо уничтожить владельца/окно. | Обход выполняется по копии registry, владельцы проверяются через `QPointer`; уничтожение окна прекращает dispatch. Это предотвращает инвалидирование итераторов и обращение к прежнему окну. |
| Средний: устаревшие действия | Подсказка могла удерживать действие для удалённого или изменённого сообщения/view. | Подсказки инвалидируются при изменении данных, layout, viewport и удалении связанных объектов; перед активацией проверяется актуальное сообщение/view. |
| Высокий: локальный доступ | Сервер локального управления не проверял UID принятого peer. Особенно существенен Linux abstract socket, где нет файлового ACL. | Проверка kernel credentials: `getpeereid` на macOS/BSD, `SO_PEERCRED` на Linux; чужой peer отклоняется до обработки команд. Файловые сокеты и Windows pipe ограничены `UserAccessOption`. Linux abstract transport сохранён. |
| Средний: время жизни IPC | При реальном smoke команда `CMD:quit;` воспроизвела SIGSEGV: синхронный shutdown очищал список клиентов, а `Sandbox::readClients` продолжал запись ответа через инвалидированный итератор (`QIODevice::write`). | Завершение отложено через `Qt::QueuedConnection` до окончания текущей обработки команд. Добавлен повторяемый macOS smoke с пустым профилем и проверкой PID peer через ядро. |
| Средний: сохранение защищённых медиа | Внешний просмотрщик и массовая загрузка могли обходить часть ограничений сохранения/самоуничтожения. | Перенесены точечные исправления upstream: защищённые медиа открываются штатным внутренним просмотрщиком; запрещённые элементы исключаются из bulk download. |
| Средний: файлы | Общий каталог временного перекодирования не получал явных пользовательских прав. | Перенесена установка прав чтения/записи/прохода только владельцу каталога. Отказ ОС в смене прав и враждебные filesystem races отдельно не воспроизводились. |
| Средний: граница буфера | Декодеру изображения мог передаваться размер, не соответствующий доступным байтам. | Перенесён переход на фактический load size и дополнительно применён `_data.left(_loadSize)`, который ограничен размером `QByteArray`. |
| Высокий: зависимости | Локальная OpenSSL 3.2.1 совпала с 10 CVE; Little CMS 2.16 — с тремя записями memory safety. | Обновлены исходные pins и реально используемые библиотеки: OpenSSL 3.5.8 и Little CMS 2.19.1. Для новых коммитов OSV не вернула записей. Применимость каждого CVE к конкретной конфигурации Telegram не утверждается. |
| Средний: цепочка поставки | Часть внешних GitHub actions использовала перемещаемые теги и ветки. | 15 разных версий actions закреплены по полным SHA, теги оставлены в комментариях. Все 88 внешних `uses` теперь закреплены; нормализованное содержимое workflows идентично прежнему. |

## Зависимости и остаточные находки

build libraries и четырёх модулей Qt из установленного SBOM. Это сканирование

## Секреты и дополнительные проверки

Gitleaks 8.30.1 получен из официального release, checksum проверен.
История форка на момент сканирования: 29 коммитов, новых утечек не найдено.
Сканирование архива исходников дало пять срабатываний на публичные значения
upstream; соответствующие файлы были идентичны базе. Итоговое сканирование
изменённых файлов, новых security sources и 11 изменённых файлов `lib_ui` /
`lib_base` дало одно срабатывание: прежнее публичное значение в Windows CI.
Текст срабатывания присутствует в исходной базе. Значения в отчёт не включены.

Просмотрены обработчики копирования/отправки/редактирования/удаления,
проверки прав, lifetime асинхронных callback, JSON config/editor, локальный IPC
и CI. В добавленных production-строках форка эвристический поиск не выявил
новых сетевых API, запуска shell, обходов TLS или приватных ключей.
Это ограниченный поиск и ручной анализ конкретных изменений.

`core/update_checker.cpp` идентичен базе. В данном локальном build cache
`DESKTOP_APP_DISABLE_AUTOUPDATE=ON`: свежий DMG нужно устанавливать вручную.
Настройка автообновления в рамках аудита не менялась.

## Проверка результата

Проверки исходников, библиотек и сборки:

- Native Debug `test_vim_keymap`: 892/892 проверок; итоговый native Release
  после добавления проверки управляющих символов: 893/893.
- `vim_keymap_wiring_tests.cmake`: 96/96 source-level checks.
- Полная macOS arm64 Release-сборка `Telegram` с обновлёнными библиотеками,
  затем успешная пересборка последних исправлений lifetime и IPC.
- Native OpenSSL: 145 тестов в `test_evp`, `test_ec`, `test_rsa`, `test_rand`,
  `test_ige`; Little CMS: `testcms` 1/1.
- Syntax parsing всех workflow YAML; каждый внешний action закреплён по SHA;
  после нормализации комментариев/refs workflows идентичны исходным.
- `git diff --check`, LF без BOM для изменённых текстовых файлов.

Регрессионные тесты находятся в
`Telegram/SourceFiles/tests/vim_security_tests.h` и используют реальный Qt:
обычные/password/NoEcho inputs, вложенные редакторы, sensitive hints,
подавление после смены фокуса, форматирование и очистка журнала,
native local socket для своего UID и отклонение disconnected socket.
Source-level checks подтверждают расположение защитных вызовов, но не
заменяют выполнение полного сценария с аккаунтом.

Отдельный экземпляр итогового подписанного приложения запущен с новым пустым
профилем: запуск PASS, automation по умолчанию отклонена, kernel peer PID
совпадает с PID тестового экземпляра, владелец сокета — текущий UID,
права сокета `0700`. Команда `CMD:quit;` завершила процесс с кодом 0.
Этот тест воспроизводил SIGSEGV до исправления отложенного shutdown.
