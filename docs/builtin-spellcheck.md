# Встроенная проверка орфографии

Telegravim использует Hunspell для проверки слов на macOS, Windows и остальных
поддерживаемых Unix-платформах. Русский и английский словари включены в ресурсы
приложения. Проверка и подсказки выполняются локально в существующей фоновой
очереди; сообщения не отправляются внешнему сервису проверки.

## Принятые решения

- Цель: подчёркивать опечатки и исправлять слово с клавиатуры в view mode.
- Выбран единый Hunspell и фиксированные словари. Системные движки отклонены
  из-за различий между ОС и определения языка отдельных русских слов.
- LanguageTool отложен: грамматика всей фразы требует отдельного решения и
  более тяжёлой интеграции.
- Русский и английский включаются однократно через KV-настройку
  `spellcheck-bundled-defaults-v1`. Существующие дополнительные языки и
  выключенная пользователем проверка сохраняются.
- Файлы встроенных словарей восстанавливаются из ресурсов при запуске сессии;
  `QSaveFile` заменяет каждый файл атомарно. Пользовательский словарь не
  затрагивается. Дополнительные языки доступны через прежний менеджер.
- `Ctrl+E` означает физический Control, в том числе на macOS. В русской
  раскладке работает та же клавиша `У`. Команда действует в view mode в поле
  сообщения. Стрелки и `j/k` выбирают вариант, Enter заменяет слово, Esc
  отменяет меню. Отмена редактирования остаётся в истории QTextDocument.
- Подсказки отменяются при изменении документа, движении курсора или смене
  фокуса во время ожидания. Уничтожение поля отменяет доступ к его меню.
- Для русского меню `Ctrl+E` дополнено локальным частотным подбором. Восемь
  вариантов ранжируются по близости написания и частоте словоформы. Учитываются
  перестановки, пропуски букв, соседние клавиши ЙЦУКЕН и типичные звуковые
  замены. Небольшое преимущество первого варианта Hunspell сохраняет полезные
  морфологические догадки при близких оценках. Подбор выполняется в отдельной
  фоновой очереди; отмена действует на обе стадии запроса.

## Словари

Источник: [LibreOffice/dictionaries](https://github.com/LibreOffice/dictionaries).
Точная ревизия, размеры и SHA-256 записаны в
[`SOURCE.json`](../Telegram/Resources/dictionaries/SOURCE.json).
Условия распространения сохранены рядом в `LICENSE_ru_RU.txt` и
`LICENSE_en_US.txt` и включены в ресурсы приложения.

Русский `.dic` хранится двумя текстовыми частями, перечисленными в `parts`:
проверка PR ограничивает один файл 2 МБ. При установке части объединяются
побайтно в исходный `.dic`; SHA-256 в манифесте относится к объединённому файлу.
Содержание словаря не изменено, обе части доступны обычному просмотру diff.
В английском `.aff` и файле его лицензии удалены конечные пробелы строк для
проверки whitespace; правила и текст лицензии сохранены. Манифест содержит
контрольные суммы поставляемых файлов и исходников до этой нормализации.

При обновлении словарей заменяйте файлы из фиксированной ревизии источника,
обновляйте манифест и проверяйте регрессии на той же версии Hunspell, которая
идёт в сборку. Словари не изменяются вручную для прохождения отдельных примеров.

## Частотные подсказки для русского

`ru_frequency.json` содержит 53 908 словоформ из
[wordfreq (Robyn Speer)](https://github.com/rspeer/wordfreq), ревизия
`912caf64b657478d1dff1138efdc078947d54bb1`. Данные распространяются по
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).
Полные уведомления об авторстве включены в JSON и `LICENSE_ru_frequency.txt`,
а также в ресурсы приложения и установочный образ.

Подмножество включает русские слова длиной до 24 букв с частотой Zipf >= 3.00,
принятые поставляемым Hunspell. Варианты Hunspell, отсутствующие в корпусе,
сохраняются среди кандидатов с оценкой на уровне порога корпуса. Английские
варианты и обработка ссылок используют прежний механизм. Самостоятельной
автозамены, запросов к внешнему сервису и обучения на переписке нет.

Исходный файл `wordfreq/data/large_ru.msgpack.gz` и `NOTICE.md` следует получать
из указанной ревизии. Их SHA-256 проверяет
`Telegram/build/generate_russian_suggestions.py`; скрипту нужен `msgpack==1.1.2`
только при обновлении данных. Для проверки слов используется
`Telegram/build/filter_russian_suggestions.cpp`, собранный с тем же Hunspell,
что и приложение. Например, после сборки macOS:

```sh
xcrun clang++ -O2 -std=c++17 -arch arm64 -DHUNSPELL_STATIC \
  -ITelegram/ThirdParty/hunspell/src/hunspell \
  Telegram/build/filter_russian_suggestions.cpp \
  out/cmake/external/hunspell/Release/libexternal_hunspell_bundled.a \
  -o .local/filter-russian-suggestions
python Telegram/build/generate_russian_suggestions.py \
  .local/wordfreq/large_ru.msgpack.gz .local/wordfreq/NOTICE.md \
  .local/filter-russian-suggestions
```

Приложению Python и скачанный исходный корпус не требуются. JSON содержит
происхождение, описание преобразования и хеш русского словаря; изменение
данных должно сопровождаться проверкой качества подсказок.

## Проверка и ограничения

`test_vim_keymap` проверяет офлайн-установку двух словарей в пустой каталог,
восстановление повреждённого словаря, сохранность пользовательских слов,
русские и английские опечатки, `е/ё`, добавление и удаление слова,
смешанный русский/английский текст, раскладки и модификаторы клавиш,
меню вне фокуса поля, выбор через `j/k`, замену и undo, `Esc`,
отмену устаревшего результата и отключённую проверку.

Проверки русского ранжирования включают 17 опечаток с ожидаемым первым
вариантом: в том числе `превет` -> `привет`, `севодня` -> `сегодня`,
`зделать` -> `сделать`, `сообщениие` -> `сообщение`. Отдельно проверяются
добавление отсутствующего у Hunspell варианта `появляется` для `появлсяет`,
сохранение регистра, замена только выбранного слова, Undo, навигация по меню
и отмена устаревших результатов. Для диагностического вывода этого набора
можно запускать тест с `TDESKTOP_TEST_RUSSIAN_SUGGESTIONS_REPORT=1`.

Это проверка отдельных слов: смысл фразы, грамматика и случайный пробел внутри
слова требуют отдельного решения. В неоднозначных случаях правильный вариант
не обязан быть первым; пользователь выбирает замену сам. Новые термины и имена
можно добавлять в личный словарь.

Общий код и одинаковые данные обеспечивают общую основу проверки; успешная
сборка и тесты на macOS не заменяют запуск тестов и приложения на Windows
и Linux.
